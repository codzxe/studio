## Notes
- **"effectcraft" references**: `effectcraft-*` is the product's own crate/identifier namespace used consistently across all 54 files (imports like `effectcraft_raster::Image` in every file; GPU labels `"effectcraft kernels"` context.rs:540; UI strings like `ocio.rs:692` `CONFIGS = &["Built-in (EffectCraft minimal)", ...]` and `paint.rs:121` "original EffectCraft data"). This is the app's own branding, **not** upstream drift — removal would mean a product-wide rebrand (crate renames + the handful of user-visible strings, which could be made theme/config-driven independently). No per-line listing since it would be ~500 identical entries.
- **No upstream leftovers**: no `graphite`/upstream-repo/URL/donation references anywhere in S081–S090; no `todo!`/`unimplemented!`/`unreachable!` in any scope file; the only `unwrap()`s are in `#[cfg(test)]` code.
- **Golden tests** (S086 `tests/*`): exact f32-bit hashes are pinned only for aarch64 macOS; on other platforms the tests assert determinism only. This is documented in-file as a libm-precision tradeoff, not a stub — flagging so the fix wave knows coverage on other platforms is determinism-only.
- The GPU crate's per-frame CPU plan builders (fx_gen2/fx_sim/fx_particles) intentionally read the frame back once for effects that need pixels (Paint Bucket, Eyedropper Fill, CC Ball Action, Shatter); that's documented design, not a finding.

- sim2.rs Foam's pop-push loop (1803-1814) is O(popped × bubbles) per step but bounded by the 3000-bubble cap — acceptable; noted only.
- Everything else in these 54 files held up remarkably well under read: the wgpu error-scope/pool/readback machinery in context.rs, adv3d.rs's pre-flight checks, util.rs's filters and ocio_config.rs's bounded YAML parser are all carefully guarded and brute-force tested.

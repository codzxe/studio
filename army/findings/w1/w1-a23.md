## Notes
- **api-client is NOT in S202–S212.** The mission blurb mentions packages/api-client, but in the manifest it is S228–S237 (manifest-w1.md lines 1644-1681) — outside this agent's range; not audited here.
- **The dead contracts cluster is one fix:** `packages/contracts/src/{brand,context,entities,engine,sse}.ts` are all absent from the barrel and have zero repo importers (verified by import sweep). `context.ts`/`entities.ts` import `Role/ModelAlias/PlanId` from `brand.ts`; nothing imports any of the five. Deleting them as a unit removes the contradictory PLANS pricing, the fabricated COMMAND_ALLOWLIST/EFFECT_REGISTRY, the second AgentBatch schema, and the duplicated ROLE/MODEL/BRAND/LIMITS seams in one pass. contracts/tests has no test files importing them (only src/route modules are tested).
- **effectcraft rename is a two-sided change:** the `window.effectcraft`/`window.effectcraftLoad` global is defined by the frozen editor dist host page (`apps/web/public/editor/index.html`, sourced from `editor/apps/effectcraft-web/web/index.html` — READ-ONLY upstream). A bridge-side rename must ship together with the host-page script or every handshake fails with `EDITOR_NOT_READY`. The dist tests (dist.test.ts) mount the global by name and will pin the rename.
- **EFFECTCRAFT_CLI_PATH** is baked into `.env.example` via `renderEnvExample()` and asserted in env.test.ts (lines 385-394, 632-633) — a rename needs the test + generator + any deploy env updated in the same commit; the underlying binary name `effectcraft-cli` is upstream's, so the var rename should keep the resolution-order doc honest about what it points at.
- **Batch bounds have two homes that agree today:** contracts `MAX_BATCH_STEPS/BYTES/TIMEOUT_MS` (static, browser-shippable) vs config env `AGENT_BATCH_MAX_STEPS/BYTES/TIMEOUT_MS` (server-tunable, defaults 100/2 MB/60 s). If an operator tightens the env values the bridge will still validate against the static constants until the gateway rejects — acceptable, but the fix wave should document which side wins.
- **Verified non-bugs** (checked because they look suspicious): bridge batch `timeoutMs` DOES survive `normalizeAgentBatch` (AGENT_BATCH_SCHEMA declares `timeoutMs` optional, so it is not stripped); `Math.min(parsed.timeoutMs ?? callTimeoutMs, MAX_BATCH_TIMEOUT_MS)` is correct; events.ts reducer transition rules match their doc comments; editor-bridge `withTimeout` clears its timer on both settle paths; config `creditsToMicrocredits` NaN/Infinity ordering is safe (isFinite check catches both).
- The `STRIPE_WEBHOOK_SECRET` required-unconditionally vs `STRIPE_SECRET_KEY` local-optional asymmetry in config/env.ts is deliberate (spec table + local fixture uses a placeholder) — flagged here for awareness, not reported as a bug.
- brand.test.ts's `EffectCraft` mentions are the ADR-0006 guard's own test fixtures — intentional, not leaks.

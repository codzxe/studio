### S174 — web lib non-chat part 2 (autosave engine)
- apps/web/src/lib/editor-session/autosave.ts:257 | MED | BUG | `if (inFlight !== null) return inFlight; // skip/dedup while a save is in flight` | explicit saves dedupe onto an in-flight tick save that read bytes BEFORE the user's latest edits; a `saveNow("before-close")` that lands during an in-flight upload returns `saved:true` for the stale bytes, the page then closes and there is no next tick — post-T0 edits are lost from the cloud (Cmd+S during an upload gets the same lying "saved" outcome, though the next tick recovers it). Fix: for explicit reasons, chain a fresh save after the in-flight one settles (`inFlight.then(() => startSave(reason))`) instead of returning its outcome.

## Notes
- `window.effectcraft` is the REAL runtime seam, not a leftover comment-only name: the frozen editor dist exposes `window.effectcraft` / `window.effectcraftLoad` and its build artifacts are named `effectcraft_web.js` / `effectcraft_web_bg.wasm` / `snippets/effectcraft-web-<hash>/`. Every occurrence in my scopes is either (a) a production URL string that must track the dist (editor-warmup.ts:43/211/215 + its test), (b) a type import from @studio/editor-bridge (autosave.test.ts:12), or (c) doc comments (index.ts:16, load.ts:11, types.ts:8). Removal is a cross-package effort: regenerate the dist under new names, rename `Effectcraft*` types in @studio/editor-bridge, update all host call sites — or keep upstream names and make the URL list manifest-driven (removes the hardcoding without touching the upstream crate). The fix wave should treat this as one coordinated rename, not per-file edits.
- The one data-loss-adjacent bug is autosave.ts:257 (before-close dedupe); everything else is degraded-mode/hygiene. The autosave engine is otherwise solid: single-flight, conflict park (terminal), error park (recoverable via explicit save), hash dedupe, safeNotify hook isolation, dispose semantics — all covered by real tests.
- No SSE, drag/resize/dock code lives in these scopes (chat panel drag/resize/dock and composer.tsx itself are S181+); no upstream Graphite leftovers found in any of the 28 files.
- The editor-session suite now runs under the main vitest config (include widened to `src/**`), so findings in those tests will surface in CI; the local config (S177 finding) is the stale residue of the pre-widening era.

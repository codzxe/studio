## Notes
- **Highest-value fix**: the round-12 auto-apply run-status gap (m5-agent-edits + m12 RED assertions) is a real product bug, not just test debt — every client auto-apply drive 409s RUN_NOT_ACTIVE until `routes/turn.ts`'s plan route transitions the run to `awaiting_approval`. Fix is one `runs.update` in the plan route; two e2e journeys go green with it.
- **EFFECTCRAFT footprint in my scopes** is confined to the e2e specs (5 files: m3-device-lost, m5-agent-edits, m5-mock-create, m8-renders comment, visual-verify) — the runtime source of the name is the committed wasm dist itself (`public/editor/effectcraft_web.js`, `public/editor/snippets/effectcraft-web-6247e0b7c298e283/`, outside my scopes). The e2e layer can be decoupled cheaply via one `editorGlobal()` alias + runtime snippet-dir discovery; true removal needs a dist rebuild/rename wave.

- Duplicated helpers across the e2e specs (`waitForSignInHydration`, `openSeededEditor`, `editorFrame`, `okEnvelope`, `EffectcraftGlobal`) are deliberate per a stated policy ("e2e specs never import sibling spec files") — I did not report the duplication itself, but any fix that adds a shared alias module could absorb these too.

- panel.tsx spec constants (SIDEBAR_MAX_W=560, DOCK_EDGE_PX=32, DETACH_THRESHOLD_PX=8) are pinned by the ECUX spec docs — left alone.

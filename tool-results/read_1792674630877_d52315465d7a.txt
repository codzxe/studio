    18→    18→/**
    19→    19→ * Studio schema (Postgres, drizzle-orm) — PRODUCT_ARCHITECTURE §9.1 (all tables),
    20→    20→ * §9.3 (versions/conflict), §8.8 (credit ledger) + Better Auth 1.7 core/org/api-key/admin
    21→    21→ * plugin tables, verified against `getSchema()` of the installed better-auth.
    22→    22→ *
    23→    23→ * Conventions:
    24→    24→ * - text primary keys (`${prefix}_${uuid}`) generated app-side; timestamps with
    25→    25→ *   time zone (JS Date mode).
    26→    26→ * - Column names are snake_case; TS property names are camelCase.
    27→    27→ *   EXCEPTION: Better Auth tables — property names MUST match the plugin model
    28→    28→ *   field names exactly (the drizzle adapter addresses columns by property name).
    29→    29→ * - Tenant scoping: content tables carry `workspace_id` (or scope through
    30→    30→ *   `project_id` -> projects.workspace_id). Cross-tenant access must read as
    31→    31→ *   "not found" (§12.1) — enforced in `src/repos/*`, not here.
    32→    32→ *
    33→    33→ * Decisions (documented for reviewers):
    34→    34→ * - `project_versions` is NOT unique on (project_id, sha256): re-saving identical
    35→    35→ *   content is a legitimate action and §9.3 forbids rewriting history; the
    36→    36→ *   object store dedupes the blob itself (§9.2 content-addressed). The composite
    37→    37→ *   index exists for fast "is this content already stored" lookups.
    38→    38→ * - `credit_ledger` is append-only by convention; balance is SUM(amount) under a
    39→    39→ *   per-workspace advisory lock (see src/repos/ledger.ts).
    40→    40→ * - `renders`, `comments` and `agent_*` scope through `project_id` per §9.1; the
    41→    41→ *   repos join projects to enforce tenancy.
    42→    42→ * - `projects.current_version_id` and `project_versions.parent_version_id` are
    43→    43→ *   plain text columns WITHOUT FK constraints: they form a circular reference
    44→    44→ *   pair with `project_versions.project_id`, and both are written only inside
    45→    45→ *   repo transactions that hold the project row lock (src/repos/versions.ts),
    46→    46→ *   so integrity is enforced where the conflict rules live (§9.3) without
    47→    47→ *   making schema-level DELETE semantics impossible.
    48→    48→ */

   463→   463→// Section 7 — Credit ledger (§8.8, §10.2) — append-only
   464→   464→//   grant   +N   purchase / plan allowance / top-up pack
   465→   465→//   adjust  ±N   manual corrections, storage overage, promos (may be negative)
   466→   466→//   reserve −N   hold at run start (pessimistic: balance drops immediately)
   467→   467→//   commit  −M   actual cost at settle time (bounded by the run's hold)
   468→   468→//   refund  +R   release of an unspent hold (full refund on failure/cancel)
   469→   469→// balance = SUM(amount); writers serialize per workspace via pg_advisory_xact_lock.
   470→   470→// ─────────────────────────────────────────────────────────────────────────────

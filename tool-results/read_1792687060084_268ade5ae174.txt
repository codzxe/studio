    17→    17→## 1. What “done” means
    18→    18→
    19→    19→The v1 loop:
    20→    20→
    21→    21→```text
    22→    22→landing → sign up → create workspace → start trial (card) → dashboard
    23→    23→  → create/open project → editor loads (unmodified EffectCraft)
    24→    24→  → upload/import assets → chat: “make this title pop”
    25→    25→  → agent inspects context → plan card → preview
    26→    26→  → apply (one atomic engine.batch) → undo/redo
    27→    27→  → version saved → close/reopen intact
    28→    28→  → render/export → download
    29→    29→  → billing ledger shows credits used
    30→    30→```
    31→    31→
    32→    32→v1 is **not** done when the editor loads or the chat streams. It is done when the loop
    33→    33→above works for a new user, on a clean machine, with tenant isolation, credits and
    34→    34→recovery.

    88→    88→## 3. Milestones
    89→    89→
    90→    90→### M0 — Baseline, fork and build (2 weeks)
    91→    91→
    92→    92→**Goal:** a clean, reproducible repository that builds the real editor and the SaaS
    93→    93→shell. Remove the old PhotoCraft critical path without losing salvageable work.
    94→    94→
    95→    95→Tasks:
    96→    96→
    97→    97→1. **Preserve the current tree before deleting anything.** `studio-main` is not a git
    98→    98→   repository. Initialise git, commit the baseline, add a remote, and tag
    99→    99→   `pre-effectcraft-baseline`. If a remote is not available, create a zip outside the
   100→   100→   repo. Do not delete code until this is done.
   101→   101→2. **Audit and classify the old code.**
   102→   102→   - Keep/adapt: `packages/billing` (ledger/tests), `packages/storage` (validation,
   103→   103→     S3), `packages/config` (env parsing), selected UI primitives, auth patterns.
   104→   104→   - Reference only: `packages/agent`, `packages/tools`, `packages/engine-client`,
   105→   105→     `apps/worker` — built around PhotoCraft and not reusable as-is.
   106→   106→   - Archive: `vendor/photocraft`, `engine-patches`, PhotoCraft fixtures, the mock
   107→   107→     coffee demo, static-design templates.
   108→   108→   - Delete from the active path only after the archive tag exists.
   109→   109→3. **Fork EffectCraft into `editor/`.**
   110→   110→   - Pin an exact commit in `editor/UPSTREAM.md`.
   111→   111→   - Add the upstream remote; verify `cargo test --workspace` and the native CLI build.
   112→   112→   - Build the web editor (`cargo xtask web`) and record wasm size, load time and
   113→   113→     browser requirements.
   114→   114→   - Verify `window.effectcraft` methods needed by the bridge:
   115→   115→     `execute`, `request`, `inspect`, `renderFrame`, `addFile`, `readFile`,
   116→   116→     `saveToBrowser`, `screenshot`.
   117→   117→   - Verify `engine.batch` atomicity, `$N` references, rollback and one-undo-step
   118→   118→     behavior with a real project.
   119→   119→   - Record every build/integration patch in `editor/UPSTREAM.md`; there should be
   120→   120→     zero UI patches.
   121→   121→4. **Create the target monorepo skeleton.**
   122→   122→   - `apps/web`, `services/gateway`, `services/worker`, `packages/ui`,
   123→   123→     `packages/contracts`, `packages/editor-bridge`, `packages/config`.
   124→   124→   - If a new Hono gateway is cleaner than repairing `openapi.ts`, rebuild it and copy
   125→   125→     route logic deliberately. Do not spend a week fixing a scaffold that has never
   126→   126→     booted.
   127→   127→5. **Local environment without Docker.**
   128→   128→   - Postgres, Valkey, MinIO native installs or services.
   129→   129→   - LiteLLM in a Python venv; one model alias working.
   130→   130→   - `.env.example` with every variable and a startup check that fails fast on missing
   131→   131→     secrets.
   132→   132→   - `pnpm dev` starts web + gateway; editor is a second terminal or proxied build.
   133→   133→6. **CI skeleton.**
   134→   134→   - Web: typecheck, lint, unit tests, build.
   135→   135→   - Gateway: typecheck, tests, migration check.
   136→   136→   - Editor: `cargo test`, `cargo clippy`, wasm build at the pin.
   137→   137→   - Licence/attribution check.
   138→   138→7. **Docs reset.**
   139→   139→   - Point `docs/AGENTS.md` at this plan and ADR 0006; mark the PhotoCraft sections
   140→   140→     historical.
   141→   141→   - Record the pin and attribution in `ATTRIBUTION.md`/`NOTICE`.
   142→   142→   - Add `docs/phases/M0.md` with evidence: build logs, wasm size, load time, test
   143→   143→     results.
   144→   144→
   145→   145→**Exit criteria**
   146→   146→
   147→   147→- `git log` has a baseline commit and an EffectCraft pin commit.
   148→   148→- `editor/` builds native + wasm from a clean checkout.
   149→   149→- The editor opens at `/editor/` with COOP/COEP and no console errors.
   150→   150→- The SaaS shell starts with a health page.
   151→   151→- One real LiteLLM chat completion succeeds from a script.
   152→   152→- The old PhotoCraft path is archived, not silently half-live.
   153→   153→- No product code imports deleted modules.
   154→   154→
   155→   155→**Risks to resolve now**
   156→   156→
   157→   157→- EffectCraft's web build may require a specific Rust/wasm toolchain; pin it.
   158→   158→- `saveToBrowser` may not mark the project clean; test and record before autosave.
   159→   159→- The wasm bundle may be too large for the target hosting; measure before M3.

   163→   163→### M1 — Auth, workspace and shell (3 weeks)
   164→   164→
   165→   165→**Goal:** a real tenant boundary and a navigable SaaS shell.
   166→   166→
   167→   167→Tasks:
   168→   168→
   169→   169→1. **Better Auth** with Drizzle/Postgres.
   170→   170→   - `organization`, `apiKey`, `admin` plugins; email/password, Google, GitHub.
   171→   171→   - Session cookies, CSRF, rate limits; no custom auth tables.
   172→   172→   - Roles: `owner | admin | editor | viewer`; server-side permission checks.
   173→   173→2. **Workspace lifecycle.**
   174→   174→   - Create workspace, slug availability, switch workspace, invite/accept, remove
   175→   175→     member, transfer ownership.
   176→   176→   - Audit events for invites, role changes, removals and API keys.
   177→   177→3. **API foundation.**
   178→   178→   - Hono (or Next route handlers) with Zod envelopes, request ids, error mapping.
   179→   179→   - Tenant-scoped repository layer; every query filters `workspace_id`.
   180→   180→   - Idempotency middleware for mutations.
   181→   181→4. **App shell.**
   182→   182→   - Left rail, top bar, workspace switcher, command palette, toasts, error boundary.
   183→   183→   - Route groups: `(marketing)`, `(auth)`, `(app)`.
   184→   184→   - Middleware protects app routes; unauthenticated → sign-in with return path.
   185→   185→5. **Onboarding.**
   186→   186→   - Create workspace → use case (skippable) → trial start.
   187→   187→   - Trial start is stubbed until M6; use a dev entitlement flag.
   188→   188→6. **Tests.**
   189→   189→   - Auth flows, invite acceptance, role matrix, cross-tenant 404s, API-key scopes.
   190→   190→   - Playwright: sign up → create workspace → invite → accept → role gate.
   191→   191→
   192→   192→**Exit criteria**
   193→   193→
   194→   194→- Two workspaces cannot see each other’s data, tested at API and UI level.
   195→   195→- Owner/admin/editor/viewer permissions match the matrix in
   196→   196→  `PRODUCT_ARCHITECTURE.md`.
   197→   197→- Invites work for new and existing users.
   198→   198→- Shell is keyboard-navigable and responsive at 390/768/1440.
   199→   199→- No auth logic outside Better Auth.

   203→   203→### M2 — Projects, assets and versions (3 weeks)
   204→   204→
   205→   205→**Goal:** the data model and storage that the editor and agent depend on.
   206→   206→
   207→   207→Tasks:
   208→   208→
   209→   209→1. **Projects CRUD.**
   210→   210→   - Name, slug, description, thumbnail, archived; create from blank or import
   211→   211→     `.ecproj`; duplicate; delete with confirmation and recovery window.
   212→   212→2. **Assets.**
   213→   213→   - Upload (multipart or presigned), MIME sniffing, size/duration/dimension probe,
   214→   214→     SHA-256 dedupe, signed download URLs, workspace/project scoping.
   215→   215→   - Stable virtual paths: `/assets/<assetId>/<sanitizedName>`.
   216→   216→3. **Versions.**
   217→   217→   - Immutable snapshot upload with `base_version_id`, SHA-256, size, label,
   218→   218→     `agent_run_id`; current version pointer; list/restore (restore creates a new
   219→   219→     version).
   220→   220→   - Optimistic concurrency: `409 PROJECT_VERSION_CONFLICT`.
   221→   221→4. **Lease.**
   222→   222→   - Acquire/renew/release; 2-minute heartbeat, 5-minute expiry; read-only for others.
   223→   223→5. **Storage quotas.**
   224→   224→   - Per-plan limits; reject over-quota before upload; usage counters.
   225→   225→6. **Project hub UI.**
   226→   226→   - Overview, Versions, Comments (placeholder), Renders (placeholder), Activity.
   227→   227→   - Thumbnail generation stub (real render in M8).
   228→   228→7. **Tests.**
   229→   229→   - Signed URL scope, cross-tenant access, version conflict, restore, lease expiry,
   230→   230→     duplicate/delete recovery, quota rejection.
   231→   231→   - Load a 24 MP asset and a 100 MB video without buffering the whole file in memory
   232→   232→     on the server.
   233→   233→
   234→   234→**Exit criteria**
   235→   235→
   236→   236→- Create → upload asset → save version → list → restore works via API and UI.
   237→   237→- A stale `base_version_id` returns 409 and never overwrites.
   238→   238→- A second editor gets read-only and cannot mutate.
   239→   239→- Object keys never leak in API responses.
   240→   240→- Quotas enforced server-side.

   244→   244→### M3 — Editor host, bridge and autosave (4 weeks)
   245→   245→
   246→   246→**Goal:** the unmodified EffectCraft editor runs inside the product, loads a cloud
   247→   247→project and saves it back.
   248→   248→
   249→   249→Tasks:
   250→   250→
   251→   251→1. **Editor build pipeline.**
   252→   252→   - Production wasm build, hashed assets, service worker, COOP/COEP headers.
   253→   253→   - Serve at `/editor/`; dev proxy from Next.js; prod Caddy route.
   254→   254→   - `?empty` start; no restore of local browser sessions.
   255→   255→2. **`packages/editor-bridge`.**
   256→   256→   - Typed wrapper around `window.effectcraft`; timeout, retry, error normalisation.
   257→   257→   - Same-origin iframe; readiness handshake; version check.
   258→   258→   - Event bus for ready/focus/resize/error; no polling of the DOM.
   259→   259→3. **Load sequence.**
   260→   260→   - Fetch manifest → register assets by virtual path → upload `.ecproj` → open →
   261→   261→     restore active comp/playhead/selection.
   262→   262→   - Missing asset placeholders + non-blocking banner.
   263→   263→4. **Autosave/versioning.**
   264→   264→   - Dirty tracking, debounce, `saveToBrowser`/`readFile`, SHA-256, version upload.
   265→   265→   - Save on explicit `Cmd/Ctrl+S`, after agent apply, before close, and every 30s
   266→   266→     while dirty.
   267→   267→   - Conflict UI with compare/restore; never silent overwrite.
   268→   268→5. **Editor page chrome.**
   269→   269→   - Full-bleed iframe; floating project bar (auto-hide), back button, presence,
   270→   270→     Share, read-only badge.
   271→   271→   - No persistent top nav, no injected CSS, no editor restyle.
   272→   272→6. **Keyboard/focus.**
   273→   273→   - Same-origin listener forwards `Cmd/Ctrl+L/K/I` from the iframe to the chat.
   274→   274→   - Editor keeps its own shortcuts; no global capture that breaks it.
   275→   275→7. **Failure handling.**
   276→   276→   - Unsupported GPU/browser message; wasm load failure with retry; editor crash
   277→   277→     recovery to last version; unsaved-changes guard.
   278→   278→8. **Tests.**
   279→   279→   - Playwright: open project, edit, save, reload, verify composition tree.
   280→   280→   - Visual regression: editor screenshot equals upstream (allowing only the floating
   281→   281→     product bar/chat).
   282→   282→   - Bridge contract tests with a fake editor.
   283→   283→
   284→   284→**Exit criteria**
   285→   285→
   286→   286→- A real project opens, edits, autosaves and reopens with the same comps/layers.
   287→   287→- Assets resolve after reload; missing assets do not block the project.
   288→   288→- Autosave creates immutable versions and handles 409.
   289→   289→- Read-only lease is enforced in the UI and API.
   290→   290→- Screenshot diff confirms EffectCraft's editor UI is unchanged.
   291→   291→- Editor ready p75 < 6s warm cache, < 12s cold on the reference machine.

   338→   338→
   339→   339→### M5 — Agent edits: plan, preview, apply, undo (4 weeks)
   340→   340→
   341→   341→**Goal:** the agent changes the project safely, atomically and reversibly.
   342→   342→
   343→   343→Tasks:
   344→   344→
   345→   345→1. **Write tools.**
   346→   346→   - `create_composition`, `create_text`, `set_properties`, `add_effect`,
   347→   347→     `set_keyframes`, `apply_preset`, `undo_run`, `save_version`.
   348→   348→   - Each returns a proposed batch; no direct execution.
   349→   349→2. **Plan compiler.**
   350→   350→   - Model plan → Zod `EditPlan` → command batch validation against
   351→   351→     `command.describe`/JSON Schema.
   352→   352→   - Allowlist command ids; max 100 steps, 2 MB, 60s; reject unknown/ambiguous.
   353→   353→   - `$N` reference handling; layer id resolution from names with disambiguation.
   354→   354→3. **Plan/preview UI.**
   355→   355→   - Plan card with risk, affected layers, credit estimate, steps.
   356→   356→   - Preview before/after frame at playhead or first affected time.
   357→   357→   - High-risk confirmation; cancel.
   358→   358→4. **Apply path.**
   359→   359→   - Client calls `effectcraft.execute("engine.batch", batch)`.
   360→   360→   - Atomic rollback; one undo step.
   361→   361→   - Post result + sha256 to gateway; create version; commit credits.
   362→   362→5. **Undo/redo.**
   363→   363→   - `edit.undo` for the whole run; card state changes; version remains.
   364→   364→   - Re-apply only if `base_version_id` matches; otherwise explain.
   365→   365→6. **Auto-apply (optional, off by default).**
   366→   366→   - Only low-risk, reversible edits; server-side policy; per-user setting.
   367→   367→7. **Agent UX polish.**
   368→   368→   - Inline edit (`Cmd/Ctrl+K`), agent mode (`Cmd/Ctrl+I`), quick actions.
   369→   369→   - Diff cards; “View in timeline”; error/clarify cards.
   370→   370→8. **Tests.**
   371→   371→   - Golden prompts against a real project: text animation, color change, effect add,
   372→   372→     keyframes, multi-layer edit.
   373→   373→   - Failure injection: invalid command, mid-batch failure, editor disconnect,
   374→   374→     version conflict, zero credits → rollback/no charge.
   375→   375→   - `panic_hunt` equivalent for tool args: adversarial JSON never crashes gateway or
   376→   376→     editor bridge.
   377→   377→   - Playwright: prompt → plan → preview → apply → undo → redo.
   378→   378→
   379→   379→**Exit criteria**
   380→   380→
   381→   381→- At least 10 representative prompts apply successfully on the corpus project.
   382→   382→- Every applied run is one undo step and one version.
   383→   383→- A failed step never leaves a partial edit.
   384→   384→- The model never receives raw command registry or filesystem paths.
   385→   385→- High-risk actions always require confirmation.
   386→   386→- Apply p75 < 300ms for ≤ 20 steps (excluding preview render).
   387→   387→

   390→   390→### M6 — Billing, credits and entitlements (3 weeks)
   391→   391→
   392→   392→**Goal:** a real paid product with no free tier and correct money paths.
   393→   393→
   394→   394→Tasks:
   395→   395→
   396→   396→1. **Plans and entitlements.**
   397→   397→   - Trial (14 days, card required), Starter, Pro, Studio; seats, models, storage,
   398→   398→     render minutes, credit allowance.
   399→   399→   - Server-side entitlement checks; UI reads entitlements, never hardcodes.
   400→   400→2. **Stripe.**
   401→   401→   - Checkout (subscription + top-up packs), customer portal, webhooks with signature
   402→   402→     verification and idempotency.
   403→   403→   - Trial start, renewal, past due, cancel, grace period; no work deletion.
   404→   404→3. **Credit ledger.**
   405→   405→   - Append-only `credit_ledger`; reserve/commit/refund; idempotency keys.
   406→   406→   - Reserve at run start; commit model + render + storage; refund difference/failure.

   659→   659→### 7.2 Golden agent prompts
   660→   660→
   661→   661→Maintain `evals/prompts/` with at least 30 prompts across:
   662→   662→
   663→   663→- Create a title comp with text and a background.
   664→   664→- Animate scale/position/opacity with specific timings.
   665→   665→- Add and tune an effect.
   666→   666→- Change brand colours across layers.
   667→   667→- Reorganize/rename layers.
   668→   668→- Add a lower third.
   669→   669→- Create a 3D-ish camera move (within engine support).
   670→   670→- Ambiguous target → must clarify.
   671→   671→- Destructive request → must confirm.
   672→   672→- Impossible request → must explain, not hallucinate.
   673→   673→
   674→   674→Score: plan validity, apply success, visual sanity (frame compare), undo success,
   675→   675→credits accuracy, latency. Target ≥ 90% valid plans, ≥ 95% apply success on valid
   676→   676→plans.

   678→   678→### 7.3 Security tests
   679→   679→
   680→   680→- Cross-tenant reads/writes for every resource.
   681→   681→- Role escalation via API, UI and agent tools.
   682→   682→- Signed URL expiry/audience; object key guessing.
   683→   683→- Upload polyglots, zip bombs, huge dimensions, path traversal, MIME spoofing.
   684→   684→- Prompt injection in layer names, comments, asset metadata and `.ecproj` text.
   685→   685→- Tool arg fuzzing: NaN, Infinity, negative sizes, huge arrays, prototype pollution.

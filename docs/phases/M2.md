## Exit-criteria status

- **Create → upload asset → save version → list → restore works via API and
  UI** — DONE in pieces: the API journey is proven end-to-end across the four
  gateway suites; each UI surface is component-tested (146 web tests); the
  single dedicated browser journey does not exist (gaps, below).
- **A stale `base_version_id` returns 409 and never overwrites** — DONE
  (pinned: "rejects a STALE base with 409 PROJECT_VERSION_CONFLICT and creates
  no row"; the repo locks the project row and asserts the expected version
  inside the write transaction).
- **A second editor gets read-only and cannot mutate** — DONE at the API
  (refused acquire → `readOnly:true`; `requireLeaseForMutation` → 409
  `LEASE_HELD` on version writes and project-scoped asset creation) and in the
  editor host UI (M3 read-only banner + suspended autosave; M7 added the
  queue/election UX on top).
- **Object keys never leak in API responses** — DONE (asset/version DTOs carry
  ids + signed URLs only — `toDto` mappings in `routes/assets.ts:96` and
  `routes/versions.ts`; storage keys are server-side only; the suites exercise
  every read path).
- **Quotas enforced server-side** — DONE at create/upload time (maxProjects on
  create + duplicate; storageBytes projected at descriptor time; flat env
  caps). The usage-aggregate *read* is owed (gaps, below).

## Gaps / owed (honest — matching W1-A7's milestone audit)

1. **No large-file streaming proof.** §M2.7 asks for "load a 24 MP asset and a
   100 MB video without buffering the whole file in memory on the server". The
   asset path satisfies this **by design** — the client PUTs directly to
   storage via the signed URL and the gateway's verify step reads a 512 KiB
   bounded head (`routes/assets.ts:70/:301`) — but **no test evidences a real
   large upload end-to-end**. Honest asymmetry, stated so nobody over-reads
   the design: **version snapshots DO transit the gateway as whole buffers**
   (`routes/versions.ts:170/:189`), bounded by `PROJECT_MAX_BYTES` — acceptable
   for `.ecproj` JSON, but it is not the streaming path §M2.7 describes.
2. **No dedicated M2 browser journey** — create → upload → save → list →
   restore is covered piecewise (gateway suites, component tests, M3's editor
   flow), but `apps/web/e2e/` holds no M2 spec (only chat/m5/m7/m8/m9), and no
   CI exists to run one.
3. **Storage used-bytes aggregate read absent** — quota is enforced as a
   projected check at descriptor time (`repos/assets.quota`); there is no
   gateway route that reports current usage, and the billing page's storage
   meter reads entitlements, not usage (W1-A7 TOP-20 #15).
4. **Lease heartbeat client unwired** — §M2.4's "2-minute heartbeat" is
   server-capable (`repos.leases.renew`; re-acquire extends the TTL — pinned
   by test) but the editor host re-checks the lease on mount/focus only; no
   background heartbeat is scheduled (first recorded in M3.md known tails #3;
   still true — `leases.renew` has no web-side caller).
5. **Delete "recovery window" is retention, not a feature** — soft-delete
   keeps the row + snapshot bytes and releases the project-quota slot, but
   there is **no user-facing un-delete route**; archive/unarchive
   (`PATCH archived`) is the reversible path. Stated so the plan wording is
   not over-read.

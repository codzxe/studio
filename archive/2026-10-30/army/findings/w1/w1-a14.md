### S131 — pdf crate src

- editor/crates/pdf/src/image.rs:138 | HIGH | BUG | `let mut out = Vec::with_capacity(w * h * n);` where `n` comes straight from a `/DeviceN` names array (`color.rs:148` `a.get(1)…map_or(1, <[Obj]>::len)`, no cap) via `image.rs:240` `cs.components().max(1)` — a hostile `/ColorSpace [/DeviceN [<tens of millions of names>] …]` with a ≤64-Mp image drives a multi-TB `with_capacity` → allocation abort, bypassing the try-reserve hardening used everywhere else (`read.rs` Budget, `object.rs` MAX_INFLATED). Fix: cap components (Func::MAX_IO-style, ≤32) and use `checked_mul` + `try_reserve_exact`.
- editor/crates/pdf/src/font.rs:410 | MED | BUG | `for c in first..=(*last as u32).min(first + 65535) {` — unchecked `u32` add on file-controlled `/W` first CID; `4294967295 0 25` overflows (debug panic, release wrap). Same at line 441 (W2 ranges). Fix: `first.saturating_add(65535)`.
- editor/crates/pdf/src/object.rs:570 | MED | BUG | `if pred < 10 { return Some(data.to_vec()); }` — `/Predictor 2` (TIFF horizontal differencing, ISO 32000-1 Table 10) is silently passed through raw, so images from TIFF-predictor files decode with wrong colours instead of failing or being skipped. `tests.rs:315-316` codifies the passthrough (`predictor == 2 → expected == input`, real prediction of `[10,20]` w/ Colors 1 is `[10,30]`). Fix: implement TIFF predictor 2 (~10 lines: per-row delta per component) or return `None` + a skip note like other unsupported features.
- editor/crates/pdf/src/ps.rs:1184 | MED | BUG | `"save" => { … self.saved.push(self.gs.clone()); self.gs.depth = self.b.depth(); …}` pushes the copy *before* recording the current builder depth, so the saved state carries a stale depth (unlike `gsave` at 1213-1216 which sets the copy's `depth`). A `restore` then closes builder groups opened before the `save` (e.g. a `clip` between the last save/grestore and a `save` is discarded). Fix: mirror `gsave` — `let mut g = self.gs.clone(); g.depth = self.b.depth(); self.saved.push(g);`.
- editor/crates/pdf/src/read.rs:45-57 | LOW | BUG | whole-file scan for literal `trailer` + `/Encrypt` — an uncompressed stream containing the bytes `trailer << /Encrypt` (e.g. an embedded PDF) makes a non-encrypted document fail with `Error::Encrypted`. Fix: trust the shared parser's decryption error (line 58-62 already maps it) and demote the byte scan to a fallback.
- editor/crates/pdf/src/ccitt.rs:497-552 + object.rs:373 | LOW | BADCODE | `p.end_of_line = flag("EndOfLine", false);` is parsed into `ccitt::Params` but `decode()` never reads it (EOL handling is unconditional) — dead parameter. Fix: honour it or delete the field.

## Notes

- **Strongest finding** is pdf/image.rs DeviceN `n` → `Vec::with_capacity(w*h*n)` allocation abort: it is exactly the bug class the crate's own comments say they defend against ("a failed allocation aborts the process", object.rs:304-309); the per-file tests (`hostile_structures`, absurd-dimension tests) cover image *sizes* but not the colour-space component count, which `Func::MAX_IO` caps elsewhere but `Cs::Tint` does not.
- **Predictor 2 passthrough** (object.rs:570) is codified by `tests.rs:315-316` — fixing the code requires fixing that test's expectation too; the current expectation is provably wrong against ISO 32000-1 (real TIFF prediction of `[10,20]` with Colors=1 is `[10,30]`).
- **ps.rs save/restore asymmetry** is the only PS-interpreter logic issue found; the interpreter otherwise carries meticulous budget/limit/stack hardening with hostile-input tests.
- The psd crate is the cleanest scope (zero effectcraft references, budget-hardened decoders with reference-implementation equivalence tests). `memory_tests.rs`/`tests_opt.rs` deliberately keep the *old* decoders verbatim as references — not dead code.
- Lottie's export/import pair is unusually complete (mattes, parenting, separated dimensions, expressions, text animators, style runs), with honest warnings for everything dropped. The `.lottie` deflate gap is the one real interop hole; zip.rs's path-traversal guard (`is_relative_name`) is good.
- automation/tests.rs (1382 lines) and lottie/src/tests.rs (831 lines) exist on disk but are not listed under any manifest scope (S138/S140 list only the src files given) — possible coverage gap for the fix wave to be aware of.
- `server.rs:284` gates "modern" MCP result fields on protocol version ≥ "2026-07-28" — a future-dated revision (speculative forward-compat); harmless but worth confirming against the eventual real revision string.
- Effectcraft naming totals in scope: pdf 31, model 2(+tests), psd 0, svg 21, lottie 46, raster 3, automation 50 ≈ 153 occurrences across ~35 files; all are crate names (`effectcraft-svg/-text/-path/-geom/-color/-time/-keyframe/-project/-engine/-raster`) or "EffectCraft" strings — a coordinated crate-rename plus a single product-name constant (server identity, URIs, env var, CLI name, dotLottie generator) removes them all mechanically.

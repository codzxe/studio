# Migrations (`packages/db/migrations`)

Forward-only, reviewable SQL generated by Drizzle (spec §4, §12.2). This directory
is the single migration stream for every `src/schema/*` table in `@studio/db`.

## Layout

```
migrations/
├── README.md            # this file
├── 0000_<name>.sql      # one file per migration, applied in order
└── meta/
    ├── _journal.json    # drizzle-kit's apply ledger — never hand-edit
    └── 0000_snapshot.json
```

## Workflow

1. Change a table in `packages/db/src/schema/*.ts` (each file has one owning build
   agent — see `docs/AGENTS.md`).
2. Generate SQL from the package root:
   ```sh
   pnpm db:generate        # drizzle-kit generate; writes 000X_<name>.sql here
   ```
3. **Review the SQL in the PR.** A schema change is only real once its SQL has
   been read by a human: constraint drops, `NOT NULL` additions and index builds
   are the ones that bite.
4. Apply, in every environment before production (ADR-0002: migrations are never
   tested on production first):
   ```sh
   pnpm db:migrate          # drizzle-kit migrate; records progress in meta/_journal.json
   ```
5. Before production, the migration is tested against a **restore of the latest
   prod backup** (§12.2).

## Rules (spec §4 / §12.2)

- **Forward-only.** There are no down migrations. Rollforward is the only path.
- **Never hand-edit in prod.** Never edit or reorder an already-applied
  migration file; schema fixes are new migrations appended on top.
- **Never hand-edit `meta/`** — drizzle-kit owns the journal and snapshots.
- Generated SQL only: `pnpm db:generate` is the sole author of files here.
- `drizzle.config.ts` scopes drizzle-kit to the `public` schema
  (`schemaFilter`) and the barrel at `src/index.ts`, so every schema agent's
  tables share this one stream.
- Both commands require `DATABASE_URL` in the environment (drizzle-kit does not
  read `.env` by itself — export it, or use `node --env-file` when shelling in).

The seed script (`scripts/seed.ts`) is **not** a migration: it is idempotent demo
data, re-runnable at any time, and never run against production.
